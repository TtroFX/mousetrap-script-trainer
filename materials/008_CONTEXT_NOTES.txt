CONTEXT RECORD CONTRACT
For every canonical speechId, the application/build pipeline derives one context record with:
- sceneId
- speechId
- speakerId
- unitId
- sourceOrdinal
- previousSpeechId: immediately preceding canonical speech in the same scene, or NONE at scene start
- nextSpeechId: immediately following canonical speech in the same scene, or NONE at scene end
- cueSpeechId: previousSpeechId when present; otherwise SCENE_START
- contextWindow: previous/current/next canonical speech references
- translationRef: speechId -> 004
- grammarRef: speechId -> 007
- addresseeMode: EXPLICIT_ONLY or CONTEXTUAL
- intentMode: SOURCE_SUPPORTED_ONLY

DETERMINISTIC ID RULES
SCN-A01-S01 speech N -> act1-scene1-speech-{N:04d}
SCN-A01-S02 speech N -> act1-scene2-speech-{N:04d}
SCN-A02-S01 speech N -> act2-speech-{N:04d}
Speech ordinal N maps to Unit sequence N+1 because Unit 0001 is PREAMBLE.

ADJACENCY RULE
Within a scene:
- previousSpeechId(N) = speechId(N-1), N>1
- nextSpeechId(N) = speechId(N+1), N<scene speech count
- no cross-scene adjacency is created
- a scene boundary is represented explicitly rather than pretending the first line of the next scene is a conversational continuation

ADDRESSEE / INTENT SAFETY
Exact addressee and dramatic intent are recorded only when directly supported by the source context or validated learning material. When multiple people are present and the addressee is not source-explicit, the value remains CONTEXTUAL rather than guessing a specific person. This is intentional completeness, not an unresolved QA flag.
